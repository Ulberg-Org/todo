The apply failed because Azure refuses Defender until the subscription is registered for `Microsoft.Security`. `Microsoft.EventHub` isn't registered either, so dev's next `start` would have failed the same way.

**Cause:** these service registrations were only ever done by hand, in `bootstrap/bootstrap.sh`, which runs once. So every new Azure service needed a manual step that nobody remembered.

**Fix, in platform #75:**
- `shared` registers every service the stacks use, as code, from one list with a test.
- Each registration is a small command run by CI. It does nothing for services already registered, and never unregisters any.
- Defender's plan waits for its registration. `shared` is applied before the environment, so Event Hubs is ready before dev starts.
- Shared's tests pass 7/7, there are no warnings, and formatting is clean. Its CI is running.
