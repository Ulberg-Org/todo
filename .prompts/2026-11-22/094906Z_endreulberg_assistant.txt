Both rules are in the style guide as a new **§9 "Native F# first"**, and CI now enforces the lambda part. Formatting moves to §10.

**What I checked:**
- **Online:** `_.Name` is F# 8's shorthand for a lambda that only reads a property, calls a method or indexes its argument. It can't be used where `_` already discards an argument ([Announcing F# 8](https://devblogs.microsoft.com/dotnet/announcing-fsharp-8/), [Lambda expressions](https://learn.microsoft.com/fi-fi/dotnet/fsharp/language-reference/functions/lambda-expressions-the-fun-keyword)). Microsoft's [style guide](https://learn.microsoft.com/en-us/dotnet/fsharp/style-guide/) doesn't cover these cases, so the rules are ours.
- **The reference app:**
  - it uses `_.Member` about 612 times;
  - `fun x -> x.Prop` appears only about 27 times, mostly in framework builder callbacks;
  - it turns values into Option and Result with pipelines (`Option.map`, `Option.defaultValue`, `Result.map`, `Result.bind`, `Result.requireSome`);
  - it never builds a Result with `if`.

**§9 says:**
- **Turn values into `Option` and `Result` with pipelines, not `if`:** `Result.requireTrue` then `Result.map`, `Result.requireSome`, `Option.map` then `Option.defaultValue`. Choices are unions with `match`, loops are `List.map` and folds. It includes your `parse` as the before-and-after example.
- **Lambdas as short as they can be:**
  - `_.Name` when a lambda only reads a member;
  - `fun _ ->` when the argument isn't used, including `()`;
  - a function by name instead of a lambda that only calls it, e.g. `Deployment.RunAsync(run)`.
