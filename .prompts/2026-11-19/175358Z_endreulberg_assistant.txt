**Phase 1 grilling, round 1.** Some terms first, then the questions. As before, each question has my recommendation; answer "yes" to accept it, or give your own.

**Terms:**
- **Walking skeleton:** the thinnest possible version of the app that still goes through every layer (code → container → CI → telemetry), so every later feature only adds flesh to bones that already work.
- **Trivy:** an open-source scanner. It looks inside the built container image and lists every known security hole (a "CVE") in the operating-system packages and libraries in it, plus risky settings.
- **SBOM (Software Bill of Materials):** a machine-readable ingredients list of the image: every package and version. When the next big vulnerability hits, you search the SBOMs to see in seconds whether you're affected, instead of guessing.
- **OTLP / OpenTelemetry:** the open standard our backend uses to send traces, metrics and logs to Grafana.
- **Testcontainers:** tests that start a real throwaway Postgres in Docker for each test run, so database code is tested against the real thing, not a fake.

❓ **Q2** - **When does Trivy fail the build?** Failing on everything blocks you on vulnerabilities nobody can fix yet; failing on nothing makes the scan decoration.

➡️ Fail on **critical and high** vulnerabilities **that have a fix available**. Unfixable ones are reported but don't block. Exceptions go in a committed file, each with a reason and an expiry date, so nothing is ignored forever.
