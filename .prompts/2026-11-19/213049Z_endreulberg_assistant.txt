**On the lag:** yes, it's a real concern and simple to handle. Brand-new releases are where supply-chain attacks happen (a hijacked maintainer account publishes a bad version, and it's usually caught within days). Dependabot supports this directly with a **cooldown**: it waits N days after a release before proposing it. **Security fixes skip the cooldown,** so urgent patches still arrive immediately.

The Kubernetes version itself is different: Dependabot doesn't track AKS versions, so a Kubernetes upgrade stays a deliberate change in one file (Q16), done when AKS has had the version for a while.

|---|---|
