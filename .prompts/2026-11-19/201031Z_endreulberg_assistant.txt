**Lessons to apply when queues and the outbox arrive** (the D50 notifications):
1. **Carry the whole `traceparent`, not just the trace ID,** in every message and outbox row, written by the code that publishes.
2. **Consumers restore it as the parent of a real span,** not only in the logs. That's the proper fix for their gap 1. For a batch of messages, link each message's trace to the batch span.
3. **Every consumer does this, enforced by a test,** so no listener silently starts a fresh trace (their gap 3).

5. **Keep the trace ID on stored rows where it helps** (outbox, audit), so you can get from a row back to the trace.
