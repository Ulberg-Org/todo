Exactly that, and it's already where the line runs. The platform only does what isn't about the app's data model:

| Platform (`database/`, same locally and in Azure) | App repo (migrations, run as `todo_migrator`) |
|---|---|
| The database exists | Tables, columns, indexes, constraints |
| The roles and who signs in as them (passwords locally, Entra in Azure) | Seed or reference data |
| An **empty** schema `todo`, owned by `todo_migrator`, and the default privileges: what the migrator creates, `todo_app` may read and write, `todo_readonly` may read | Per-app tuning: indexes for its queries, statistics targets, table storage settings |
| Access rules: read-only by default, 30-second limit, no `CREATE` in `public` | Anything the app's code depends on |
| Observability: `pg_stat_statements` and the monitor role | — |

The default privileges are what make the split work. The app's migrations never grant anything: every table the migrator creates automatically gets the right rights for the app and for readers. Today the todo database is still empty, so nothing has moved yet.
