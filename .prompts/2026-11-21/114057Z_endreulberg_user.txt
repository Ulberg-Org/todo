  ## 5) apomonosi/sandboxing PR #20
  https://github.com/apomonosi/sandboxing/pull/20
  
  - Status: merged Oct 10, 2026 (commit 13103d8 into apomonosi:main). The fetch truncated the page and the trailing summary did not cover enforcement; the mechanism below comes from the verbatim description and commit messages.
  - Why pf fails: "Lima always gives the guest a user-mode NIC whose traffic the hostagent re-originates as ordinary host connections, so a guest with root routes around any filter."
  - Mechanism: "It refuses every outbound connection except to the instance's pinned SSH port and its egress proxy on the host's loopback." The proxy is a per-instance HTTP CONNECT/forward proxy with a default-deny allowlist; it refuses deny-LAN ranges and host loopback, and fails closed.
  - Pre-boot checks: `limactl edit` pins the instance config with no extra NICs; refuses templates or override.yaml that would bypass the sandbox, and non-vz VM types.
  - Post-boot probe: probes from inside the guest that direct egress fails, and stops the instance if it does not.
  - Direct-route answer: by design, no. The only NIC is the usernet, whose traffic becomes hostagent connections, and the sandbox denies all but the proxy and ssh ports. The commit message says "not yet a live install", so the post-start probe still needs verification on hardware.
  - Caveat: the proxy matches hostnames from the client's CONNECT request, so the TLS-hostname caveat from the Anthropic guide applies.
  
  ## Conclusion: most robust known design
  1. Proxy env vars and guest firewalls cannot stop a root guest. Only no NIC, or host-side enforcement in a process the guest cannot touch, is robust. Anthropic's vsock / `--network none` pattern and Firecracker `isolated` mode do this on Linux.
  2. On Lima, the closest known design is apomonosi #20: confine the hostagent with `sandbox-exec` so its only loopback egress is the proxy port and the ssh port; use a default-deny proxy allowlist; probe from inside the guest as root.
  3. Confinement is not total: the sandbox covers only loopback, so LAN and Tailscale need separate deny rules (apomonosi deny-LAN; boxery #4). sandbox-exec is deprecated and its behaviour on Darwin 27.2 is untested.
  4. Credentials: keep real keys in a host-side proxy and give the guest only per-VM capability tokens (coop's coop-proxy pattern).
  5. Lima's native egress policy (#5820 / #4326) is not usable now.
