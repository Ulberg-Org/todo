**What I'd add, most valuable first:**

1. **Toxic flow analysis ("lethal trifecta", Trial in Vol 35).** This is the real gap. A trifecta is private data, untrusted content and a way to send data out, all in one agent. In your setup Claude reads the database (private data). It reads logs and traces through Grafana, and those can carry text that users typed (untrusted content). It can also write public PR bodies and run web searches (a way out). D78 limits the network, but it doesn't close this path. Phase 8 makes it worse, because users' agents will read other users' shared content. Write the analysis down once in `PLAN.md`, one row per agent profile and MCP tool, and decide which part of the trifecta to break for each.
2. **Progressive context disclosure (Adopt) and agent instruction bloat (Caution).** `AGENTS.md` loads in full every session. §4 is mostly one-time setup steps that belong in a linked doc. On top of that come 21 memories and D1–D90. The radar's advice matches your own "be lazy" rule: turn each rule into a CI check where you can, and keep a short index that links to the rest. Some memories repeat AGENTS.md §6 almost word for word, and those could go.
3. **Mutation testing (moved to Adopt in Vol 35).** This catches tests that pass without checking anything, which matters when agents write the tests. You already found one example: `dotnet test` exits 0 without running any tests. The catch is that Stryker.NET supports C# only, as far as I know, not F#. So this may mean a small check of your own, or waiting. Check before planning it.
4. **Promptfoo or a similar eval and attack-test tool (Trial), from Phase 8.** It would run repeatable prompt-injection tests against your `/mcp` tools. It fits next to your "untrusted content marking" work.
5. **Risk-tiered oversight, and the "human-in-the-loop theater" warning.** Every PR needs your approval. That's fine now, but if Claude's PRs get large, consider requiring a deeper review only for changes to access, infrastructure or hooks.

**Probably skip:** Act (running GitHub Actions locally) adds another tool to your supply chain for little gain. Agent Scan sends metadata to Snyk. OpenSpec and Spec Kit overlap with `PLAN.md`, and the radar now warns about spec sprawl. Most of the platform and framework entries (LangGraph, Bedrock AgentCore and similar) don't apply to you.
