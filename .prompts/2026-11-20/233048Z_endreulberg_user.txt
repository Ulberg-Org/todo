  (2) Locked Down policy and rule scope
  - Initialise Locked Down: yes, `sbx policy init deny-all`. The docs list the values: "`allow-all` (Open), `balanced` (Balanced), and `deny-all` (Locked Down)". `sbx policy init` only works before a preset is set. To change the preset later, use `sbx policy reset` (deletes all local rules; `--force` skips the prompt) and then choose again.
  - Allow/deny: `sbx policy allow network api.anthropic.com`, `sbx policy deny network ads.example.com`. Several hosts in one command: `sbx policy allow network "api.anthropic.com,*.npmjs.org,*.pypi.org"`.
  - Scope to one sandbox: `--sandbox <name>`, for example `sbx policy allow network --sandbox my-sandbox api.example.com`. Deny at creation: `sbx create --deny-network ads.example.com claude .` or `sbx run --deny-network ads.example.com claude` (repeatable). Remove: `sbx policy rm network --sandbox my-sandbox --resource api.example.com`. List: `sbx policy ls <name>`.
  - Pattern syntax (reference page): exact `example.com` matches that host on any port, not subdomains. `*.example.com` matches one subdomain level (`api.example.com`). `**.example.com` matches any depth (`v2.api.example.com`). `example.com:443` matches port 443 only. CIDR works for IPv4 and IPv6 (`10.0.0.0/8`, `2001:db8::/32`). Hostnames are case-insensitive. `example.com` and `*.example.com` do not cover each other.
  - HTTP rules: `sbx policy allow network api.github.com --method GET --path '/repos/org/project/**'`. Methods: `GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS, CONNECT, TRACE`, or `ANY`. Paths start with `/`, `*` is one segment, `**` is any depth. Queries use `--query 'team=platform'`. A host deny cannot be reopened by an HTTP allow. An HTTP rule only accepts a host pattern locally, and it takes one `--path` per rule.
  - Deny-over-allow: "a deny rule from any source takes precedence over an allow rule." Under Locked Down, kit rules still apply.
