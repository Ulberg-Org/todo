Agreed, and it's a real gap today. todo's `platform.yaml` routes `/`, so `/health/live`, `/health/ready` and `/version` are all reachable from outside through the gateway. `/version` gives away the exact commit and build time, which helps an attacker match us against known vulnerabilities.

**My recommendation, in short:**
- **Health checks are for Kubernetes only.** The kubelet calls the pods directly and never goes through the gateway, so health needs no route at all. It moves to a separate management port that only the kubelet can reach.
- **`/version` goes in the internal API**, behind authentication.
- **One app port per audience, enforced in both layers:**
  - **App layer:** each port has its own endpoint group and its own authentication middleware, so an endpoint can't end up on the wrong audience by accident.
  - **Infrastructure layer:** the renderer routes each audience only to its own port. The gateway also checks the token for authenticated audiences (Envoy's JWT validation), and Cilium allows each port only from the callers that audience permits.
  - **The private API** never gets a route; only declared callers inside the cluster can reach it. Deferred, as you say.

❓ **Q3 - What the audiences mean.** Here's my reading of your four; tell me where it's wrong:
- **Public:** anonymous, from the internet. Only what anyone may see: the public OpenAPI spec, perhaps a status page. Every request is logged and traced like the rest.
- **Internal:** our company's own frontends and apps. Authenticated, with our workforce identity or app identities (Entra).
- **External:** end users reaching their own data. Authenticated with External ID (customer accounts).
- **Private:** only reachable inside Kubernetes, from declared callers; stricter access control in both layers. Deferred.

The open point: todo's own frontend is used by end users. Is its API therefore **external**, with internal meaning staff tools and service-to-service calls?

Each has its own Oxpecker endpoint group and its own authentication middleware (none, Entra, External ID), so the compiler and the router decide which audience an endpoint belongs to, not a naming convention. The tests check that every endpoint answers only on its own port.
