**Worth adding now** (infrastructure only, no app features needed):

1. **Start each trace at the gateway.** Envoy Gateway can emit its own spans and access logs. A trace would then begin at the entrance, showing time spent in the gateway, and the access log line would carry the trace ID.
2. **All pod logs and Kubernetes events in Loki**, not just the app's. That means ArgoCD, Envoy, the collector, and events such as failed scheduling, out-of-memory kills, failed probes and image pull errors. Today those need `kubectl`; this lets you and me find them in Grafana.
3. **Network drops (Cilium's Hubble).** Every connection a deny-by-default rule blocks would be logged, with source, destination and the reason. That's the most useful debugging tool for our network rules. Caveat: in AKS the same flow logs need the paid add-on we just avoided, so this would be local-only, or a cost decision for later.
4. **Postgres performance (D64):** a `todo_monitor` role, Postgres's own metrics (connections, locks, cache hit rate) and per-query statistics. That shows which queries are slow and how often they run. The Postgres MCP can already explain query plans as `todo_readonly`.

   - per-service request rate, error rate and latency;

   - ArgoCD sync health;
